## 4. Архитектура модулей

### Принцип работы
1. `index.html` подключает `main.js` (как модуль).
2. `main.js` импортирует все UI-компоненты и вызывает их функции (например, `createHeader()`).
3. Каждый UI-компонент возвращает DOM-элемент, который вставляется в `#app`.
4. Все компоненты читают состояние через `state.get(...)` и подписываются на события через `state.on(...)`.

### Ключевые модули

**`state.js`** — Singleton с глобальными данными.
- `state.get('currentWeek')` — получить значение.
- `state.set('currentWeek', 2)` — установить и оповестить.
- `state.on('change:currentWeek', callback)` — подписаться на изменение.
- `state.determineWeek()` — вычислить текущую неделю (1 или 2) от даты старта.
- `state.getNow()` — **ВАЖНО**: использовать вместо `new Date()` (для поддержки отладки).

**`config.js`** — константы.
- `CONFIG.SEMESTER_START_DATE` — точка отсчета (26 октября 2026).
- `CONFIG.DEFAULT_SETTINGS` — настройки по умолчанию (тема, шрифт, группа, API погоды).

**`data-manager.js`** — главная функция `getLessonsForDay(week, day, group)`.
- Возвращает массив пар для конкретного дня с применёнными заменами.
- Используется в `schedule.js`, `timer.js`, `full-schedule.js`.

**`themes.js`** — управление темами.
- `applyTheme(themeName)` — применить тему.
- `applyFont(fontName)` — применить шрифт.
- `initThemes()` — загрузить сохранённую тему/шрифт при старте.

## 6. Логика расчётов

### 6.1. Вычисление недели
```javascript
// В state.js
determineWeek() {
    const now = new Date();
    const today = new Date(now.getFullYear(), now.getMonth(), now.getDate());
    const start = CONFIG.SEMESTER_START_DATE; // 26 октября 2026
    
    const diffDays = Math.floor(Math.abs(today - start) / (1000 * 60 * 60 * 24));
    const weekIndex = Math.floor(diffDays / 7) % 2;
    return weekIndex + 1; // 1 или 2
}
```

**Пример:**
- 28 октября 2026 → 1-я неделя.
- 02 ноября 2026 → 2-я неделя.

### 6.2. Определение курса
```javascript
const isSecondYear = group.startsWith('25'); // 25, 24, 23 → 2+ курс
const bells = isSecondYear ? BELLS.course2plus : BELLS.course1;
```

### 6.3. Логика таймера
- Пара считается 90 минут = 45 + 5 (перемена) + 40 (вторая часть).
- Если реальная длительность меньше (например, 45 минут), таймер не ищет перемену внутри.
- Прогресс-бар показывает оставшееся время до конца текущего отрезка.

## 15. Интеграция с Telegram Mini Apps

Проект работает как Telegram Mini App и имеет облачную синхронизацию без бэкенда.

**Как это работает:**
1. В `index.html` подключен скрипт `telegram-web-app.js`.
2. Файл `assets/js/telegram-storage.js` содержит обёртку `smartStorage`, которая работает как мост между обычным `localStorage` и Telegram `CloudStorage`.
3. При записи (`setItem`) данные всегда сохраняются в `localStorage`, а если мы в Телеграме — дублируются в облако.
4. При чтении (`getItem`) приоритет отдается облаку Телеграма. Если там пусто, читается `localStorage`.
5. В `state.js` и `ui/notes.js` используются асинхронные вызовы `smartStorage`. Для предотвращения перезаписи облачных данных локальными пустышками используется флаг `isLoaded`.

**Ограничения:**
- Telegram CloudStorage имеет лимит в 4096 символов на один ключ.
- Облачная синхронизация работает только между клиентами Telegram (Телефон, ПК, Веб). В обычном браузере сайт использует только локальное хранилище.
- Синхронизация происходит асинхронно, поэтому при загрузке сайт сначала показывает локальные данные, а затем обновляет их облачными (событие `ready`).
## 16. Telegram, офлайн и облако
- **Telegram Web App:** В `index.html` подключен `telegram-web-app.js`. В `main.js` работает нативная кнопка «Назад» и защита от случайного закрытия при вводе текста.
- **Синхронизация:** `assets/js/telegram-storage.js` использует Telegram CloudStorage (с приоритетом) и `localStorage` (как запасной). Настройки и заметки синхронизируются между устройствами.
- **Офлайн-режим (Service Worker):** `sw.js` использует стратегию Network First. При обновлении сайта обязательно меняй `CACHE_NAME` в `sw.js` (например, на `v5`), чтобы пользователи получили свежую версию.
- **Шрифты:** Используются оптимизированные `.woff2` файлы для быстрой загрузки.
