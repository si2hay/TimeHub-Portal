## Common Operations

### Read → Edit → Test Pattern

```bash
# 1. Read affected files
read /home/si2hay/Documents/TimeHub-PortalBETA/path/to/file:1-50

# 2. Make changes using edit tool
edit [path#tag]

# 3. Smoke test via browser or console
open file in browser, check console, verify feature works
```

### Tools Reference

| Tool | Use Case |
|------|----------|
| `read` | File ranges, directories, SQLite, JSON with jq |
| `edit` | Surgical edits with line numbers (hashline) |
| `lsp` | Symbol search, references, rename, code actions |
| `ast_edit` | Structural rewrites (codemods) |
| `bash` | File ops, counts, checksums |
| `eval` | Python/Bun for processing |
| `web_search` | External research when needed |

### Smoke Test Commands

- **Core load**: Open `index.html` in browser → check console
- **Telegram mode**: Launch in Telegram app if available
- **Feature test**: Navigate to specific feature (schedule/weather/notes)
- **No errors**: Verify no console red text, network 200s

## Known Risks

1. **Telegram integration**: `window.Telegram.WebApp` - verify API availability
2. **Service worker**: `sw.js` must register correctly in cloned version
3. **Local storage**: Clear browser data between major changes for clean state
4. **Large files**: Use `read :N-` to read large JSON/JS files in chunks
